# Docker Fundamentals and Container Lifecycle Management

Hands-on implementation of Docker architecture and container management on **Docker Desktop (macOS, Apple Silicon)**, using the Docker CLI and a small containerized NumPy deep-learning inference app.

---

## Objective

To understand Docker architecture and manage containerized deep learning applications.

## What this project covers

| # | Area | What was done |
|---|------|---------------|
| 1 | Install Docker | Verified Docker Desktop with `docker --version`, `docker version`, `docker info`, `docker run hello-world` |
| 2 | Create and manage containers | Ran `nginx:alpine` as `dl-web` with `-p 8080:80`; used `ps`, `curl`, `exec`, `logs`, `stats`, `inspect` |
| 3 | Images and registries | `pull`, `search`, `images`, `history`; built a custom image from a Dockerfile; ran and tagged it |
| 4 | Container lifecycle | `create`, `start`, `pause`, `unpause`, `stop`, `restart`, `kill`, restart policy, `rm` |
| 5 | Networking and storage | Default networks, user-defined bridge `dl-net` with name resolution, named volume, bind mount |

In total, **37 Docker CLI steps** were run and logged. 36 succeeded; step 10 (`docker inspect` with a template field that does not exist in this engine version) failed with exit code 1 and is documented in the report.

## The containerized application

`dl_app/app.py` is a small two-layer neural network forward pass in NumPy (4 samples x 8 features, 16 hidden ReLU units, 3 softmax classes). The weights are random with a fixed seed, so it is a demonstration of packaging and running a deep-learning workload in a container, **not a trained model**.

```dockerfile
FROM python:3.11-slim
WORKDIR /app
RUN pip install --no-cache-dir numpy
COPY app.py .
CMD ["python", "app.py"]
```

Build and run it manually:

```bash
docker build -t dl-app:1.0 ./dl_app
docker run --rm dl-app:1.0
```

## How to run

**Requirements:** Docker Desktop running (status *Engine running*), Python 3, internet access to pull images from Docker Hub, and a bash-compatible terminal (macOS/Linux terminal, WSL, or Git Bash on Windows).

```bash
git clone <this-repository-url>
cd <repository-folder>

pip3 install reportlab        # only needed for the PDF generated by the script
python3 task9_docker.py
```

The script creates `docker_command_log.txt`, `docker_results.json` and a basic `Task9_Docker_Report.pdf`. To rebuild that PDF with screenshots placed in `screenshots/`:

```bash
python3 task9_docker.py --pdf-only
```

Alternatively, open `Task9_Docker.ipynb` in Jupyter and run all cells.

> Note: step 37 of the script removes the demo containers, the `dl-net` network and the `dl-data` volume. Downloaded images are kept. The tag `yourdockerhubuser/dl-app:1.0` is a placeholder; nothing is pushed to a registry.

## Report

`Docker_Report.pdf` contains the objective, architecture diagrams, full source code, the complete command log with observations, ten screenshots (Docker Desktop and terminal), results, observations, limitations and conclusion.

## Known limitations

- The model is a random-weight demonstration; no GPU was used.
- Images are arm64 (Apple Silicon), so sizes and digests differ on other machines.
- NumPy is not version-pinned and the container runs as root.
- No registry push was performed.
- Only single-host bridge networking was exercised.
- Docker Desktop screenshots show resources re-created after the scripted cleanup, so their IDs differ from the log.
